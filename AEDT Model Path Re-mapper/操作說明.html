AEDT Model Path Re-mapper — 操作說明

此工具由虎門科技資深技術工程師 Jeff Hong 洪敬傑提供

本工具用於批次修正 AEDT 專案內失效的模型檔路徑。常見情境：從別台電腦或封存檔（archive）收到 .aedt 專案，模型檔（.sNp / .ibs / .cir / .ami / .dll …）仍寫死指向原電腦的絕對路徑，開啟或模擬時出現 Can't find file … / Can't interpret device … 而失敗。

核心特色
  • 一次掃描所有模型：直接掃描 .aedt 內文，涵蓋所有模型型別，不需逐一在介面裡點選。
  • Auto-match 自動配對：指定一個資料夾，依「檔名」遞迴自動找到對應檔並填入新路徑。
  • 安全：套用前自動建立時間戳備份;只關閉/重開目標專案，不影響其他正在執行的 HFSS。

2. 前置需求 / 需安裝套件

本工具不需要額外下載或 pip 安裝任何 Python 套件。全部相依元件皆為 AEDT 內建 IronPython 與 Windows .NET 既有元件。
相依項目用途來源 / 是否需安裝
os, re, shutil, datetime檔案掃描與字串取代Python 標準函式庫，內建，免安裝
clr(Python.NET / IronPython)載入 .NET 元件AEDT IronPython 內建，免安裝
System.Windows.FormsGUI 視窗與控制項Windows .NET 既有，免安裝
System.Drawing版面、字型、顏色Windows .NET 既有，免安裝
若日後改以外部 IronPython / CPython（非從 AEDT 內執行）運行，才需另行安裝對應的 pythonnet（提供 clr）及 .NET Desktop Runtime;從 AEDT Automation > Run Script 執行則完全不需要。

4. 啟動工具

  1. 保持 AEDT 開啟（其他正在跑的 HFSS 模擬可照常執行，不需關閉）。
  2. 點功能表 Automation > Run Script…。
  3. 選擇 AEDT_Model_Path_Remapper.py → 開啟，即會跳出工具視窗。

5. 介面說明

區域 / 欄位用途
AEDT project (.aedt)要修正的專案檔。預設自動帶入目前作用中的專案;也可按 Use active 重新帶入，或 Browse… 自行選檔。
Search folderAuto-match 的搜尋來源資料夾（通常選 archive 根目錄或放模型檔的資料夾）。
Scan掃描專案，列出所有模型檔參照。
Status 欄OK = 路徑存在;MISSING = 找不到;FIXED = 已指定新路徑、待套用。
Refs 欄該路徑在專案中出現的次數。
Original / New Path原始路徑（唯讀）與要替換的新路徑（可編輯）。
Auto-match依檔名自動把 Search folder 內對應的檔填入 New Path。
Set selected row → Browse file…手動為選取的那一列指定新檔（Auto-match 找不到時使用）。
Save project before closing套用前先存檔，保留你在該專案的其他變更（預設勾選）。
Reopen after fix修正後自動重新開啟專案（預設勾選）。
APPLY (backup + fix)執行：備份 → 關閉該專案 → 取代路徑 → 重新開啟。

6. 操作步驟

  1. 確認 AEDT project 為要修正的 .aedt（或按 Use active / Browse…）。
  2. 按 Scan。表格會列出所有模型參照，失效者顯示 MISSING。
  3. 設定 Search folder（按 Folder… 選資料夾），再按 Auto-match。 工具會自動把對應檔填入 New Path，狀態轉為 FIXED。
  4. 若有某列沒配到（log 顯示 - no match for <檔名>），選該列按 Set selected row → Browse file… 手動指定。
  5. 確認無誤後按 APPLY，於確認視窗按 OK。
  6. 等下方 log 顯示完成、專案自動重開後，即可重新執行模擬 / Compliance。
套用後會發生什麼：工具自動建立備份（例如 專案名.aedt.20260616_103000.bak)→ 只關閉這一個專案 → 用精準字串取代修改路徑（逐位元組無損，不破壞編碼）→ 重新開啟。 其他開啟中的專案與正在跑的 HFSS完全不受影響。

7. 疑難排解

狀況處理方式
Scan 後仍有 MISSING、Auto-match 配不到確認 Search folder 內確實有同名檔;或用 Browse file… 手動指定。
APPLY 後 log 顯示 leftover 殘留數不為 0代表還有未涵蓋的舊路徑字串。把 log 內容提供出來，即可補進取代清單。
新路徑檔案不存在該列會被略過並於 log 標示 SKIP (new file missing)，請改填正確檔。
需要還原把備份檔 *.bak 改回 .aedt 覆蓋即可。
含 AMI 的 IBIS（如 .ibs 內引用 .dll/.ami)請確保 .dll/.ami 與 .ibs 放在同一層資料夾;AEDT 會相對於 .ibs 位置尋找。
注意：本工具只解決「檔案路徑」問題，讓專案能正常開啟與讀取模型。 若模擬本身因模型內容不正確（例如 Tx/Rx buffer 型別錯置、AMI 與協定不符）而失敗，屬另一層問題，需更換正確模型，非本工具範疇。
